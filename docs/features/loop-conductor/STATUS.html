5. 卡点：真 claude E2E

四次点火，四次 403。本地 claude CLI 单独预检偶尔能成功返回 ok，但 conductor spawn 出的 maker 子进程几乎必中 403 Request not allowed。这是账号 / 配额 / 风控侧的间歇性拒绝，不是 conductor 的 bug。

诊断收敛过程（这本身就是 loop 韧性的实战检验）

  • #1 23:47 maker 秒死 403（num_turns 1, $0）→ green gate 红 → FAILED_BOX。机制正确，但把瞬态错误当成了干活失败。
  • #2 23:57 retry 后再 403，同样秒死。坐实"间歇性"。
  • #3 00:00 这次 maker 真跑了 3 个回合、烧了 $0.104 才被 403 打断 —— 证明失败可能发生在有真实进度之后，必须支持"续接"而非"从头重来"。
  • 补丁 给 lib/claude.mjs 加瞬态重试 + -r 续接 + 重试记账；测试 40 → 44 全绿。顺手挖出一个潜伏 bug：测试注入的 NODE_TEST_CONTEXT 泄漏进嵌套 green gate，导致它恒绿吞红灯 —— 此前 40 个测试碰巧没踩中。
  • #4 00:24 第 4 次 run：补丁生效，transient retry attempt 2 (status=403) 正确触发并进入退避等待 —— 但在等 15/30/60/120s 时被手动 kill。任务幂等停在 READY，状态不脏。
附带账：瞬态韧性补丁本身尚未过冷验收。它是为了打通 E2E 临时加的，按"制造与裁决分离"的规矩，它欠一轮独立 verifier 审查。已记在下一步清单里。
